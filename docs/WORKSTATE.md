## Границы и решения

- Пользователь поручил выполнить P18 с промежуточными коммитами; продолжается ранее порученное слияние принятых завершённых веток. Действующий To do list найден. P19–P32 не начинать.
- Серверные модули проверят metadata/bounds/angle/opacity/locked и multipart: ровно file+metadata, файл 1–20 МиБ, metadata до 8 КиБ, тело до 21 МиБ. Реальные байты считаются в потоке, ложный Content-Length не обходит лимит. Имя — безопасное базовое Unicode-имя; owner/ID/серверные поля клиента не принимаются.
- Проверять сигнатуру/MIME/структурную целостность PNG/JPEG/WebP, статичный одиночный кадр и реальные размеры до полного декодирования: оси до 16384, всего до 40000000 пикселей. SVG/HTML/анимации/повреждения/несоответствие MIME отклоняются. Исходные байты не перекодируются.
- Для полноценного декодирования планируется Node-only sharp с failOn=warning/limitInputPixels; для потокового multipart — busboy с ограничениями. Закрепить версии и проверить native-зависимость через npm ci. Worker и браузер не должны импортировать эти библиотеки.
- Router будет использовать подготовленный валидатор при наличии будущего images.create handler. Сейчас production handler отсутствует, после guards остаётся 501 до чтения тела. Тестовый HTTP-handler проверит путь валидации отдельно от будущей записи P19. Миграции и контракт P17 сохраняются.

## Сделано и проверки C02

- image-metadata.mjs: строгие bounds WGS84/angle/opacity/locked, defaults и patch без сброса отсутствующих значений; запрет owner/ID/лишних полей. Имя считается в Unicode-кодовых точках и не допускает путей/управляющих символов/повреждённого Unicode.
- image-multipart.mjs: busboy читает ровно file+metadata в любом порядке, сохраняет UTF-8 имя и точные байты. Файл до 20 МиБ, metadata до 8 КиБ, тело до 21 МиБ; лимиты file/field parser заданы +1 для включённой верхней границы и проверяются фактически. Переполнение/лишние части/повреждения останавливают чтение; полное тело multipart не собирается.
- request-body.mjs выделяет общий readBoundedChunks; прежние JSON/сырой body используют тот же подсчёт фактических байтов, проверки Content-Length/encoding и раннюю паузу без уничтожения сокета до JSON-ошибки.

## Сделано и проверки C03

- image-validation.mjs: сигнатуры PNG/JPEG/WebP, CRC и структура PNG, границы JPEG-сегментов/сканов, точный размер/чанки RIFF WebP. Требуется одиночный статичный кадр; APNG acTL/fcTL/fdAT и WebP ANIM/ANMF/animation flag отклоняются. Лишние байты после контейнера не допускаются.
- Предел осей 16384 и 40000000 пикселей проверяется по структуре/metadata до полного декодирования. sharp 0.35.5/libvips 8.18.7: failOn=warning, limitInputPixels=40000000, limitInputChannels=5, unlimited=false; metadata недостаточно, stats проходит реальные пиксели. Исходные байты копируются до первого await и возвращаются без перекодирования; только Buffer, никаких путей к файловой системе.

Method/Origin/session и отсутствие handler по-прежнему проверяются раньше тела; production images API остаются 501. Старые Router-тесты усилены валидными изображениями/patch, сохранены точные 21 МиБ/8 КиБ и следующий байт.
- npm run build, npm test — 142/142, включая 17 P18; целевые Node/PostgreSQL — 4/4.
